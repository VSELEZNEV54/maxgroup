# Работа над сайтом Max Group

Правило действует во всём проекте. Согласованный стек — Python 3.13, Django 5.2 LTS, Wagtail 7.4 LTS, PostgreSQL 17. Публичные страницы отдаются в HTML. Для интерактива используем JavaScript и общие CSS-токены проекта. Celery и Redis отвечают за фоновые задачи. Локальный вход — Docker Compose. Архитектура и команды находятся в [карте стека](docs/stack.md) и [инструкции разработчика](docs/operations.md).

- Выбор стека принят. Обычные правки страниц, текстов, стилей, форм и каталога выполняй сразу в этой архитектуре. Уточнение нужно при реальной неоднозначности задачи, использовании рабочих доступов или необратимом изменении данных.
- Основной локальный сайт — `http://localhost:8000/`, Wagtail — `/admin/`. Из корня выполни `make up`. После правки проверь страницу в Django; `make test` проверяет серверные сценарии, `make check-urls` — адреса текущего выпуска. Порты 4317 и 4318 могут занимать параллельные предпросмотры макетов.
- Новые типы страниц, редакторские поля и серверную логику добавляй в Django/Wagtail в `backend/`. Общий дизайн и интерактив меняй в их исходниках. Действующая вёрстка из `src/` переносится импортом. Изменения существующих импортируемых макетов проверяй через Django после синхронизации. Папки сборки `dist*` являются результатом генерации.
- Сохраняй адреса, семантический HTML, метаданные, фотографии и поведение форм. При изменении цены отличай полный расчёт, частичную стоимость и цену по запросу. Редакторские правки и черновики должны переживать повторный импорт.
- Все публичные формы пишут в локальный журнал Django. Интеграции настраиваются через окружение. Рабочие отправки, публикацию сайта и изменения DNS выполняй по отдельной задаче владельца.
- Перед правкой смотри текущий diff. В этой папке параллельно работают другие чаты. Изменяй только относящиеся к задаче файлы, учитывай незавершённую работу соседнего чата. После правки проверь затронутый пользовательский сценарий. Смену структуры, команд и интеграций отражай в документации тем же изменением.
