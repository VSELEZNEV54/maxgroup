# Работа над сайтом Max Group

Согласованный стек Max Group — Next.js 16, React и TypeScript для сайта и собственной админки, Node.js 24 для API и фоновых задач, PostgreSQL 17 для данных. Next.js отдаёт готовый HTML. Приложение размещаем на своём сервере через Docker и Nginx. [Карта стека](docs/stack.md) · [Инструкция разработчика](docs/operations.md)

Публичный Next.js уже работает. В текущем локальном выпуске редакции страниц, каталог, заявки и фоновые задачи пока обслуживают Django/Wagtail и Celery. Перенос этих функций на Node.js — отдельная задача.

- Выбор стека принят. Обычные правки страниц, текстов, стилей, форм и каталога выполняй сразу в этой архитектуре. Уточнение нужно при реальной неоднозначности задачи, использовании рабочих доступов или необратимом изменении данных.
- Основной локальный сайт — `http://localhost:8000/`, действующая админка — `/admin/`. Из корня выполни `make up`. После правки проверяй страницу через Nginx и Next.js на порту 8000. `make test` проверяет серверные сценарии и связку с Next.js, `make check-urls` — публичные адреса выпуска. Порты 4317 и 4318 могут занимать параллельные предпросмотры макетов.
- Новые публичные страницы и компоненты пиши в Next.js на TypeScript в `frontend/`. Для новых серверных функций, собственной админки и интеграций используй Node.js и TypeScript. Для исправлений действующего выпуска учитывай текущую маршрутизацию и код в `backend/`. Существующие импортируемые макеты, общие CSS-токены и скрипты находятся в `src/`. Папки `dist*` и `.next/` генерируются автоматически.
- В обычной горизонтальной кнопке используй текст действия. У вторичной ссылки вроде «О компании» достаточно подчеркивания. Стрелки оставляй для управления направлением, например в галерее или пагинации. Правило и примеры приведены в [руководстве по интерфейсу](src/GUIDE.md).
- Сохраняй адреса, семантический HTML, метаданные, фотографии и поведение форм. При изменении цены отличай полный расчёт, частичную стоимость и цену по запросу. Редакторские правки и черновики должны переживать повторный импорт.
- Все публичные формы сохраняют заявку в PostgreSQL до отправки в CRM. Подключение amoCRM или Битрикс24 настраивай на сервере для аккаунта клиента. Рабочие отправки, публикацию сайта и изменения DNS выполняй по отдельной задаче владельца.
- Перед правкой смотри текущий diff. В этой папке параллельно работают другие чаты. Изменяй только относящиеся к задаче файлы, учитывай незавершённую работу соседнего чата. После правки проверь затронутый пользовательский сценарий. Смену структуры, команд и интеграций отражай в документации тем же изменением.
